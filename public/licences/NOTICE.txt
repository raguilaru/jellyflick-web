Jellyflick -- the licences of the code it serves
==============================================

Jellyflick is a web client, so opening it makes your browser download and run
the third-party code listed here. That is distribution, and it is why these
licence texts travel with the app: they are committed in the repository, they
are copied into the container image, and the settings screen links to this
file so they are reachable from the running app rather than only from the
source.

Everything stated below was read from the installed package itself -- its own
licence file, the `license` field of its own `package.json`, the strings
compiled into the WebAssembly binary, or a font's own `name` table -- and every
component listed is one whose bytes are really in the build output. Nothing
here is taken from a summary elsewhere.

The full texts are the other files in this directory, named after the licence
they carry. Where a licence is short enough that its text *is* the notice --
MIT and the two like it -- the text is quoted in full below instead, which is
all those licences ask for.


CONTENTS

1. SUBTITLE RENDERING, COMPILED TO WEBASSEMBLY
==============================================

Jellyflick draws styled (ASS/SSA) subtitles with `jassub`, which compiles four
C libraries to WebAssembly. The browser downloads them as
`assets/jassub-worker-*.wasm` and `assets/jassub-worker-modern-*.wasm`, about
4.3 MB in total. The names and versions below are from the symbol and path
strings inside those binaries.

libass
------
  What it is:  the subtitle renderer itself -- it parses ASS/SSA subtitles and
               rasterises them, which is the whole of Jellyflick's styled
               subtitle support.
  Licence:     LGPL-2.1-or-later. Full text: LGPL-2.1.txt
  Source:      https://github.com/libass/libass

  The LGPL asks that you be told where to get the source of the library, and
  that you be able to get the source of the version actually linked here. That
  version is not a release tarball: it is libass built from the submodule
  pinned in JASSUB's own repository, by the Docker build in that repository.
  So the complete corresponding source is:

    libass upstream   https://github.com/libass/libass
    as built here     https://github.com/ThaUnknown/jassub
                      (`lib/libass`, with `run-docker-build.sh`)

  The build paths left in the binary -- `/code/lib/libass/libass/ass.c` and its
  neighbours -- are that submodule.

FriBidi 1.0.16
--------------
  What it is:  the bidirectional text algorithm, so right-to-left subtitles
               (Arabic, Hebrew) are laid out in the correct order.
  Licence:     LGPL-2.1-or-later. Full text: LGPL-2.1.txt
  Source:      https://github.com/fribidi/fribidi
               as built here: https://github.com/ThaUnknown/jassub

HarfBuzz 8.5.0
--------------
  What it is:  the text shaper -- it turns characters into positioned glyphs,
               which is what makes ligatures and complex scripts come out
               right.
  Licence:     the "Old MIT" licence (SPDX: MIT-Modern-Variant).
               Full text, with its copyright holders: harfbuzz-MIT.txt
  Source:      https://github.com/harfbuzz/harfbuzz
               as built here: https://github.com/ThaUnknown/jassub

FreeType
--------
  What it is:  the font rasteriser, which renders the glyph outlines libass
               asks for.
  Licence:     dual-licensed, FTL or GPL-2.0-or-later. Jellyflick relies on
               the FreeType Project License (FTL). Full text: FTL.txt
  Source:      https://gitlab.freedesktop.org/freetype/freetype
               as built here: https://github.com/ThaUnknown/jassub

  The FTL asks that credit be given in the documentation. This is it:

    Portions of this software are copyright (c) The FreeType Project
    (https://www.freetype.org). All rights reserved.

  `fontconfig` is *not* part of this build: JASSUB does its own font
  selection, and no fontconfig symbol appears in the binaries. Older notes in
  this repository's research that list it are out of date.

5. JELLYFLICK'S OWN LICENCE, WHICH IS NOT SETTLED YET
=====================================================

Jellyflick has not chosen a licence of its own. Until it does, the container
image's `org.opencontainers.image.licenses` label says `NOASSERTION`, which is
the honest answer rather than a placeholder: there is nothing to assert.

That choice is also what decides the rvfc-polyfill question in section 2.
A GPL-3.0 dependency linked into the bundle has consequences for the terms the
whole app can be offered under, and settling it means either taking compatible
terms or not shipping that code. It is tracked as issue #57 and is deliberately
not decided by this file, whose job is to tell you accurately what you are
running.
